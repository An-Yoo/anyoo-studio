에이전트 팀 운영기

로컬에서 도는 다중 에이전트 관제 서버 Paperclip에 Claude와 Codex 에이전트를 묶고, 게임 작업을 티켓으로 나눠 맡겨 본 기록입니다.

왜 시작했나

처음에는 대화창 하나에서 조율 모델이 구현 모델에게 직접 일을 시켰습니다. 일이 늘자 누가 무엇을 맡았는지, 어디서 멈췄는지를 사람이 머릿속으로 들고 있어야 했습니다. 일을 티켓으로 꺼내 놓고 에이전트마다 역할을 고정하면 처리량이 늘지 시험해 보기로 했습니다.

역할 분담

역할모델맡는 일
CoordinatorClaude일을 티켓으로 쪼개 배정하고, 설계를 판단하고, 결과를 화면 캡처로 확인해 완료 처리
ImplementerCodex게임 코드, Unity 빌드, 자동 검사, 커밋
ReviewerCodex구현 결과를 먼저 검토하고, 통과하면 Coordinator에게 넘김
WriterClaudeUnity 없이 하는 일 — 문안, 데이터 표, 설계서, 티켓 초안

흐름은 배정 → 구현·커밋 → 1차 검토 → 캡처 확인·완료입니다. 처음에는 Coordinator와 Implementer 둘이었는데, 한쪽 구독 사용량만 빠르게 닳는 것을 보고 Reviewer와 Writer를 더해 일을 고르게 나눴습니다.

순찰

Reviewer와 Writer는 배정을 받아야만 깨어납니다. 그래서 Coordinator에게만 10분마다 깨어나는 순찰을 걸었습니다. 깨어날 때마다 이런 것을 찾습니다.

  • 담당자가 정해졌는데 실행이 한 번도 시작되지 않은 티켓
  • 담당자가 집을 수 없는 상태로 넘겨져 멈춘 티켓
  • 사람에게 물어 놓고 답을 기다리는 질문 카드

겪은 문제

운영 첫 주에 가장 많이 배운 것은 「일이 실패한 것」과 「인계가 실패한 것」이 다르다는 점이었습니다. 멈춘 티켓 대부분은 작업이 아니라 넘김에서 멈췄습니다.

검토 대기 상태로 넘기면 아무도 깨어나지 않는다

증상 구현이 끝나 Reviewer에게 「검토 중」 상태로 넘겼는데 Reviewer가 한 번도 실행되지 않았다.

원인 그 상태는 담당자가 작업으로 집어 들 수 없는 상태였다.

고침 에이전트 사이 인계는 「할 일」 상태로 하고, 「검토 중」은 사람에게 넘길 때만 쓰도록 지시서를 바꿨다.

티켓에 묶이지 않은 타이머 실행은 아무것도 쓸 수 없다

증상 서버를 다시 켠 뒤 첫 순찰에서 모든 상태 변경과 댓글이 403·422로 거부됐다. 오류 문구가 시키는 대로 실행 ID 헤더를 붙여도 같았다.

원인 헤더가 빠진 것이 아니라, 특정 티켓에서 시작되지 않은 실행은 다른 티켓에 쓰는 주체로 인정되지 않았다.

고침 순찰은 읽기와 보고만 하고, 실제 변경은 티켓에서 깨어난 실행이 하도록 나눴다.

넘길 때마다 풀 수 없는 잠금이 생긴다

증상 담당자를 바꾸는 순간 대기 중이던 실행이 시작도 못 하고 취소되며 티켓에 「복구 필요」 잠금이 걸렸다.

고침 원인 실행이 정말로 시작 전에 취소된 경우만 찾아 잠금을 푸는 작은 도우미를 10분마다 돌렸다. 무언가를 하다 끊긴 경우는 사람이 남은 변경을 보고 직접 푼다.

인계 댓글이 자꾸 빠진다

증상 일을 마친 에이전트가 담당자만 바꾸고 무엇을 했는지 남기지 않아, 다음 에이전트가 처음부터 다시 파악했다.

고침 같은 실수가 여섯 번째 났을 때부터 인계 댓글이 없으면 되돌린다는 규칙을 실제로 적용했다.

한글이 셸에서 사라진다

증상 명령줄 인자로 넘긴 한글 댓글이 깨지거나 일부 구간이 통째로 사라졌다.

고침 본문은 항상 UTF-8 파일로 만들어 파일째 보낸다.

지금의 결론

  • 역할을 고정하니 「누가 하다 말았나」가 티켓에 남아 사람이 덜 기억해도 됐다.
  • 대신 깨어남과 인계는 믿지 말고 확인해야 한다. 순찰이 그 확인을 맡는다.
  • 겪은 문제는 모두 운영 문서에 날짜와 함께 적고, 앞의 기록이 틀렸으면 지우지 않고 정정을 덧붙인다.
